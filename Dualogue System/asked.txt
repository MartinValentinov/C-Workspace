You are asked to implement a dialogue system for a computer game.

A dialogue consists of a series of exchanges between the player and a non-player character (NPC). Each step in the dialogue contains an NPC line and possible player responses. Depending on the player's choice, the dialogue may continue along different paths.

Requirements:

Dialogue Tree Structure:

Implement a tree for the dialogue. Each node represents a step and contains:
a. NPC line
b. A list of possible player responses
c. A list of pointers to the next steps

Rules:

Each player response has a pointer to the corresponding next step. Exceptions:
a. If there is no next step after a player response, the pointer is NULL, meaning the dialogue ends with the player's line.
b. If there are no player responses, there can be exactly one pointer to the next step, meaning the NPC continues speaking.
c. If there are neither player responses nor a next step pointer, the dialogue ends after the NPC line.

Node Initialization Function:

Implement init_node that receives arguments for a node’s data, allocates memory for it, initializes it, and returns it.

Dialogue Execution Function:

Implement play_dialogue, which receives a pointer to the tree and:
a. Always starts from the root node.
b. Prints the NPC line and available player options, numbering them from 1 upwards.
c. Waits for the player to input the number of their choice.

If an invalid number is entered, display an error message.
d. Moves to the next step corresponding to the chosen option.
e. Repeats until the end of the tree is reached.
f. If there are no player options, automatically continue along the NPC’s next step. If only one option exists, it is automatically chosen.

Demo in main:

Read data from standard input to create the tree. Use init_node to initialize nodes.

Input format:

N
<Parent number 1> <NPC Line 1>
...
<Parent number N> <NPC Line N>
M
<Parent number 1> <Player Line 1>
...
<Parent number M> <Player Line M>
K
<Parent number 1> <Player number 1>
...
<Parent number K> <Player number K>


Where:

N = number of NPC lines

M = number of player lines

K = number of links connecting player lines to NPC lines

Parent number = 0 if no parent exists

Example:

4
0 Welcome to Fantasytown. How can I help you?
0 I have some armors.
0 Here is your armor.
0 Here is your armor.
3
1 I want to buy armor.
2 Buy cheap Light armor.
2 Buy expensive Heavy armor.
3
2 1
3 2
4 3


Cyclic Dialogue:

Modify the tree structure so that a next step pointer can point back to the root, allowing cyclic dialogues.

play_dialogue should be able to traverse cycles until the player exits.

Inventory and Requirements:

Extend the tree to allow player options to have requirements:
a. Add a player inventory storing item names and quantities (e.g., “1 sword”, “10 coins”).
b. Modify play_dialogue to also receive a pointer to the player inventory.
c. Each player option may have a requirement:

Specifies an item name and required quantity

Options without requirements are always selectable

Options with unmet requirements cannot be selected
d. If the player chooses an option without meeting its requirement, display a message and remain on the current step.
